Foundational · Layer 1

Platform core

The shared engineering foundation that sits beneath every product direction. Sample handling, lineage, the geo/remote-sensing substrate, the internal R&D notebook, and the benchmark server.

Work items inside
  • Sample plan designer
  • Sample lineage
  • Geo / remote sensing substrate
  • Internal notebook platform (shared with R&D)
  • Benchmark server
Built once, amortised across every product. Not a budget line under any one direction.
Definition: diffuse Implementation: medium Risk: mid
Foundational · Layer 2

Customer delivery layer

Everything that gets data and insight from our platform out to the customer — exports, APIs, generated reports, and the interactive explorer where customers click around their results.

Work items inside
  • Data export
  • API
  • Standardised report / output generation
  • Interactive result explorer
Built incrementally per product surface. Mostly clear definition, mostly low risk — the easiest piece of the stack.
Definition: clear–diffuse Implementation: easy–medium Risk: low–mid
Foundational · Layer 3

Client data normalisation

An ingestion engine that takes whatever-shape customer data comes in — different field schemas, units, sample identifiers — and normalises it to a standard the rest of the platform can use.

Work items inside
  • MIxS mapper
Required for every direction except pure soil monitoring. Without it, every customer engagement re-invents data plumbing.
Definition: diffuse Implementation: medium Risk: mid
Differentiation axis · Layer 4

Research / scientific customisation

The capability to customise scientific reasoning for each customer's specific question as a productised capability — rather than running it as bespoke R&D per engagement.

Work items inside
  • Research agent
  • Internal notebook platform (shared with Platform core)
  • Problem-specific scientific reasoning
Scale blocker if left as manual R&D. Caps how many companion-dx and trial-intelligence engagements we can run concurrently.
Definition: very unclear Implementation: very hard Risk: risky
Differentiation axis · Layer 5

Decision automation

Algorithms that move from describing what's happening in soil and crops to recommending what to do — placement, agronomic decisions, automated agronomist-style judgement.

Work items inside
  • Algorithm for placement
  • Agentic agronomist
Differentiating but the riskiest layer. Best gated behind simpler reporting products which produce the data needed to make it tractable.
Definition: very unclear Implementation: very hard Risk: very high
